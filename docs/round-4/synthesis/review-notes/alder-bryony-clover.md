# Round-4 close reading: Alder, Bryony, Clover

Inputs are the complete packages at main `58ced1ce667b3ba1ed162a0c6280959536c8bc5f`. This lane read each TeX report in full, its README, the Python companions/tests, and generated/reference Lean. Imported inputs and external repositories were treated as read-only. The lane did not run Lean, Lake, PDF tools, or Git mutations. The central synthesis runner owns fresh Lean evidence. Source anchors below are repository-relative, one-based lines at this pin; section names give additional context. `evidence/alder-bryony-clover/convergence.json` records ten editorial dimensions with separate idea/implementation classifications, qualifications, and checked nonblank source anchors. This is not novelty scoring or a measurement of independent empirical corroboration.

## Main judgment

These three proposals agree on much more than syntax. They now give meaningful implementations of two complementary components that round 3 mostly requested: **alternative conditional requirements** (Alder/Bryony), and **finite grounding from authored mathematical expressions** (Clover). No one of them implements both in a real Lean elaborator. Their common next step should connect these components at a fixed mathematical use site, retaining the existing Lean kernel and a matched ordinary-Lean baseline.

The best synthesis should preserve their differences. Alder and Bryony optimize *sets of prospective premises* for a fixed object and rule system. Clover deliberately retains one proof per atom, gives immediate unresolved routes, and measures the cost of theorem-instance generation. Treating all three as implementations of the same “property engine” would conceal what has and has not been tested. Similarly, generic implication templates exported by Alder/Bryony have weaker semantic content than Clover's reference laws for actual endomorphisms, even if every supplied file passes the central Lean run.

## Alder: distinctive value and boundaries

**Typed residual reasoning.** A pending judgment is a Lean term under an ordered obligation telescope, equivalently a function awaiting those proofs; it is not a closed fact. Data construction is separately authorized. Dependencies on proof-valued indices mean that a flat premise set is only a restricted projection of the intended system. The report also rejects classifying every metavariable merely by whether its type is `Prop`: a proposition-valued parameter can determine the statement. See *A conservative semantic core*, `docs/round-4/ideas/alder/Alder.tex:227`, `:248`, `:274`; actual nondependent parser at `companion/alder_core.py:234`.

**Minimal sufficient supports with retained proof DAGs.** For finite atoms Q, known facts K, explicit repair vocabulary M, and ground Horn rules R, label each goal with the inclusion-minimal sets S contained in M that suffice to derive it from K. Alternative routes union/minimize families; conjunction unions the supports of premises then minimizes. The empty family means no route; the singleton family containing the empty support means a closed proof. The monotone object is the upward closure of a support family, not its literal antichain. Every successful insertion adds a previously uncovered element of Q × 2^M, proving finite termination. Completeness is relative to the fixed rules and repair vocabulary, not to all true sufficient conditions. Immutable proof DAGs survive removal of dominated index entries. Sources: *The finite requirement calculus*, `Alder.tex:384`, `:397`–`:448`; implementation `companion/alder_core.py:113`–`:164`.

Its separate checker calculates actual leaf support and validates assumption, conclusion, rule and arity identities. `infer` itself accepts a caller-supplied known-proof mapping without checking every proof body; the authored CLI path validates those seeds before search and the exporter rechecks evidence. This is an explicit boundary of a search API, not an unsound CLI result: `alder_core.py:143`, `:299`, `:179`.

**Method-aware support minimization.** Filtering only after destructive antichain minimization can discard the only proof meeting a required method. Alder proposes taking a product of proposition state and finite derivation-policy automaton state. This is an unusually concrete extension worth discussing; it is not in Alder-0. Equal-support proofs also have different cost, so first-proof retention should not be sold as optimization of proof size. Sources: *Method policy*, `Alder.tex:450`–`:470`; fourth-round answer A4 at `:1139`.

**Integer affine frames.** Alder gives a source-observation interface with a concrete base input and concrete inputs realizing spanning directions. Every admissible integer observation differs from the base by an integer combination of those directions. Equality of affine maps into an abelian group then reduces to equality on those frame points. The realizers make failed checks actual input counterexamples; coverage alone supports the positive implication. Independence of directions and realization of every point in the span are unnecessary. Empty admissible domains need a separate empty-domain case. This is more general in target algebra than a rational-vector-space test, and it correctly warns against clearing rational denominators in a torsion group. Sources: *Realizable affine frames*, `Alder.tex:724`–`:812`; finite arithmetic implementation `companion/observations.py:15`–`:36`.

**A substantive new formal-series example.** For the zero-constant solution of

`Δ + 4Δ² = (4/9)Q`,

the explicit branch is `(sqrt(1 + (64/9)Q) − 1)/8`, with coefficients `a_n = (−1)^(n−1) Catalan(n−1) 4^(2n−1)/9^n` for n≥1. A unit constant coefficient of the formal derivative supports a residual-to-jet equivalence for polynomials over R[[Q]] with the fixed branch. Another exact branch can pass the residual test and still fail the requested zero-constant branch. This is an excellent example of inference returning *precision plus branch and unit obligations*, rather than a general “verified CAS” label. Sources: *Algebraic roots and precision*, `Alder.tex:611`–`:705`.

The independent analytic upgrade is explicit: for |q|<9/64 and N≥1, the tail is at most `|a_N q^N| / (1 − 64|q|/9)`, from the coefficient ratio bound. A formal jet alone does not prove convergence or this bound. The companion checks 33 coefficients and 48 perturbed residual cases using exact rational arithmetic; it does not mechanize the all-orders or analytic theorem. Sources: `Alder.tex:707`–`:720`, `:1043`–`:1051`.

**Locality and stronger consumers.** Regional derivative hypotheses retain the unspecialized induction hypothesis and only require differentiability at the attained image W(U), rather than everywhere. An a.e. equality can be upgraded to everywhere equality with continuity and positivity of every nonempty open set under the fixed measure: the disagreement set is open and null, hence empty. These are useful positive bridge theorems, avoiding both overpermissive rewriting and blanket prohibitions. Sources: `Alder.tex:504`–`:556`, `:827`–`:844`.

**Implementation limit.** Alder-0 parses opaque proposition/rule names, `assume`, `repair`, `explain`, `show`, and lexical blocks. It implements neither actual Lean expression grounding nor arithmetic/locality theorem registration. Generated `Quotient.lean` and `Locality.lean` quantify over proposition variables and rule hypotheses; their mathematical law names are not newly proved facts. Scope exit restores facts and repair vocabulary. Every `show`, including unused assertions, must close; a failed authored module creates no new CLI output. See `Alder.tex:989`–`:1056` and `alder_core.py:336`–`:350`. Phrase at `Alder.tex:580` would be clearer as “oddness and the residue condition are required by this first-coefficient route but not by the second”; do not read it as saying only those two assumptions suffice for the first coefficient.

## Bryony: distinctive value and boundaries

**The same finite calculus, a different evidence emphasis.** Bryony independently describes essentially the same minimal-support algebra and upward-closure termination proof. It explicitly relates this to assumption-based truth-maintenance, qualifier inference and provenance, rather than claiming invention. It does not delete inconsistent contexts as “nogoods”; ordinary proof by contradiction remains logically valid, while a benchmark can separately exclude such a route. Sources: *Proof-carrying requirement families*, `docs/round-4/ideas/bryony/Bryony.tex:251`–`:330`.

**Two completeness contracts.** The finite closure theorem applies to already instantiated rules. A generation procedure has its own finite arena, supported matching grammar, normalization/matching/instance budgets and completion status. New construction terms start a new epoch; unbounded epochs are not covered by the one-epoch termination theorem. This separation deserves a prominent place in the synthesis because “bounded inference” otherwise blurs search completeness with source-language coverage. Sources: *Grounding actual Lean expressions*, `Bryony.tex:332`–`:358`. The prototype starts with ground strings and does not execute that generation procedure.

**Exact snapshot binding and repair alternatives.** A certificate stores the full structured program snapshot and digest, exact goal, support, and proof tree. Replay compares the full snapshot, not only a digest. Context, candidate and policy are opaque labels but all are bound. A changed policy label invalidates replay; it does not itself filter rules. This is a useful model of identity discipline, not typed Lean context migration. The checker is separately written but unverified. Proof trees are recursively exported and can duplicate work; the first proof for an equal support can discard a cheaper or method-preferred proof. Sources: `Bryony.tex:750`–`:755`, `prototype/bryony.py:55`, `:175`, `:227`.

Bryony usefully separates a theorem's **public interface premises**, the premises supplied at one application, and the dependencies of the selected proof. None alone proves mathematical indispensability. Alternative supports can guide repair after an assumption disappears, while changed objects require new identity or transport. Sources: `Bryony.tex:396`–`:417`, *Repair means replaying a theorem*, `:729`–`:741`.

**Weighted Fubini as a less repetitive transfer example.** The source study fixes the product measure μ×(ν restricted to s), a measurable subgraph of the exact Q, scalar action and completeness structures, and the joint integrand H. Product integrability and measurable-indicator restriction license Fubini; two section identities reconstruct the displayed target. This tests theorem composition across measures and fibers, not just a one-lemma wrapper. It preserves arbitrary s-finite measures and does not add positivity, probability or an unnecessary measurable-set-s hypothesis. This is a paper/source integration specification, not executed analytical registration. Sources: *Worked analysis*, `Bryony.tex:419`–`:471`.

Two concrete semantic refinements are particularly useful:

- Strict and weak inequalities on fibers cannot be swapped casually. A one-point Ω, Q=0, unit weight/kernel and Dirac mass at zero distinguish a strict section from one including its boundary. `Bryony.tex:473`–`:476`.
- A.e. congruence of Lean's **totalized Bochner integrals** does not uniformly require integrability; Fubini's intended interchange does require the actual theorem's analytic premises. Generic insertion of “integrable” at every integral expression can unnecessarily strengthen statements. `Bryony.tex:491`–`:502`.

**Quantifier order as evidence, not a row of tags.** For every fixed real a, x≠a holds Lebesgue-a.e.; a.e. x cannot satisfy x≠a for all real a. Countable families can be collected because the exceptional sets form a countable union of null sets. This is a sharp required-premise mutation for the future frontend. `Bryony.tex:504`–`:511`; Clover gives the same mathematical trap via singleton indicators.

**Typed reifier sharing.** Bryony packages syntax, valuation and proof that its denotation equals the original expression. A shared semiring core can serve several clients, but subtraction, rational coefficients and division need typed extensions and guards. The ideal-membership example makes coefficient-ring identity concrete: X is in (2X) over Q[X], not Z[X]. Failure to find a certificate is not nonmembership. Sources: *Certified computation*, `Bryony.tex:621`–`:647`.

**Leant and observation scope.** Bryony's positive model transfer needs no observation surjectivity. A negative verdict needs a realized admissible input and the implication from a true source property to the violated model condition. The list-length image is exactly lengths n satisfying n=0 or Nonempty A; multiple observations need joint realization, not unrelated marginal witnesses. A failed completion does not justify rejecting all completions of a sketch. Sources: `Bryony.tex:571`–`:612`. None of these are newly integrated into Leant by its companion.

## Clover: distinctive value and boundaries

**Actual finite grounding.** Clover's source grammar has endomorphism binders, four fixed predicates, explicit composition, assumptions, named claims and nested scopes. Its arena contains source binders and actual subterms of target/assumptions/retained conclusions, not every composition of available functions. Backward conclusion matching generates demands and enumerates premise-only parameters over that arena; no fresh data terms are invented inside the epoch. Then ordinary finite Horn closure retains a proof per new atom. Scope/binder identities are generative, and unsupported claims do not enter known facts. Sources: *Finite inference*, `docs/round-4/ideas/clover/Clover.tex:1080`–`:1189`; `companion/clover_slice.py:218`–`:337`, `:392`–`:449`.

This is more than a generated theorem template: expressions and rule premises have a real narrow interpretation as functions on one arbitrary carrier. `CloverCore.lean` defines composition, injectivity, left inverse, involution, pointwise equality and proves seven rules (`:11`–`:43`). It is still not a Lean frontend: the Python plan checker shares AST/substitution utilities with search and never calls Lean. The mathematical core and generated examples must be separately compiled, and exact source translation remains an implementation obligation. Sources: `Clover.tex:1917`–`:1959`, `:2025`–`:2037`.

**Measured grounding overhead without a false speed claim.** For the first composition request, seven rules yield 211 ground instances, 60 atoms and 633 repeated-scan rule tests; a two-rule profile yields 16, 18 and 48 respectively. Both retain the same four-node proof, including assumption nodes. The implementation uses repeated scans, not the optimized premise-counter algorithm proposed in prose. These counts demonstrate that finite goal-triggered inference can still spend most effort outside the final proof. They do not compare Lean performance or user effort. Sources: `Clover.tex:1202`–`:1215`, `:1967`–`:1988`; reproduced `profile-comparison.json`.

**Quantified evidence remains a scheme.** A universal regional induction hypothesis must be retained as a binder telescope, not replaced by a cloud of previously used instances. Regional equality and equality at one selected point are different source nodes. The future engine must specialize the universal fact throughout a neighborhood to differentiate. This is a concrete authoring requirement beyond ground closures, currently not implemented by the endomorphism slice. Sources: *Quantified evidence*, `Clover.tex:833`–`:905`.

**The field-affine test basis.** With observation o:D→K^m, concrete inputs realize b and b+v_i, and every o(x)−b lies in the K-span of v_i. Two affine forms agree universally on admissible observations iff they agree on those inputs. Clover specializes this to `(length(xs++ys), length xs, length ys)` in Q³: the image lies in n=p+q, and three realizable points suffice. Equality of unrestricted coefficient vectors is too strong. Empty element types and a length=100 guard change the image and therefore the basis. Sources: `Clover.tex:1355`–`:1471`; `companion/affine_basis.py`.

Alder and Clover should be presented as related but different algebraic formulations. A useful general library could state the result for affine maps between modules over an explicit scalar ring, then specialize to Z/abelian groups and fields. Do not silently replace integer span by rational span for torsion-valued targets. For example, observations 0 and 2 rationally span the integer point 1, but the map n↦n mod 2 vanishes at 0 and 2 and not at 1. The positive bridge also still needs the exact candidate interpreter and source correspondence; neither finite companion implements the full Leant acceptance path.

**Required root is a precise limited policy.** Clover checks allowed rules and, optionally, the root rule of a plan via its Python API; the tiny source parser does not expose all those policy parameters. Our additional probe required `inj_transport` for an already assumed injectivity goal. Search legally returned reflexive equality and that existing goal proof beneath the required transport node. This satisfies the implemented root policy and is not a soundness bug. It demonstrates why the synthesis must not equate a required node with method indispensability or recovered human intention. Sources: `Clover.tex:514`–`:518`, `:1947`–`:1953`; `clover_slice.py:213`–`:215`, `:320`–`:327`; lane `adversarial.json`.

**Export hygiene gap found during review.** User claim names pass a broad ASCII identifier regex and are interpolated verbatim after `theorem`. A source claim named `theorem` yields `theorem theorem ...`; a claim named `compose` can shadow the opened core definition for a later composition, and `inj_comp` can shadow the later rule call. All three source specimens pass the unchanged symbolic checker/exporter. The generated files and paired input text are retained under `evidence/alder-bryony-clover/adversarial/`; the root-owned Lean runner determines the exact resulting diagnostics. These are export correctness/reliability failures, not evidence that Lean's kernel accepts false theorems. Fixes should freshen or escape declarations and use qualified semantic constants, then check exact generated source. Sources: `clover_slice.py:428`, `:465`, `:455`, `:479`, `:487`.

**Other helpful specifics.** The first Frey numerator needs p≥2 in this particular sufficient route, whereas the second needs p≥4 and no oddness/residue assumptions. The exact divisibility goal remains the fundamental guard, not a claim that these hypotheses are weakest (`Clover.tex:1527`–`:1551`). A WLOG step is an explicitly authorized construction of a normalized configuration plus admissibility and goal-transport proofs, not same-object refinement (`:922`–`:963`). The three-way coercion experiment—ordinary library rewriting, source-level canonicalizer emitting equality proofs, and kernel conversion extension—would be a better test than jumping directly from inconvenient wrappers to a new kernel (`:1814`–`:1840`).

## Recommendations and next discussion

1. **Join the two executed pieces at a real Lean boundary.** Can one request use Clover-style source-derived grounding and Alder/Bryony-style residual supports, with each rule instance a checked Lean theorem? First measure whether alternative supports actually improve diagnosis enough to justify their exponential worst case.
2. **Specify the publication contract.** Alder's CLI is all-or-nothing; Clover can export accepted theorems while marking the document incomplete. Both are defensible. The shared document model should distinguish saved partial content, individually accepted assertions, and completely verified publication.
3. **Choose what a method policy promises.** Is it an allowed rule vocabulary, a required root, a finite derivation automaton, or a richer reduction interface? State that exact contract. Do not promise mathematical indispensability from theorem occurrence or proof-node position.
4. **Separate three proof optimizations.** Inclusion-minimal assumptions, low elaboration/checking cost, and compliance with a method profile need not choose the same proof. Should retained alternatives be indexed by policy state and have bounded cost Pareto fronts? Test this before extending the core with arbitrary search.
5. **Make observation adequacy reusable.** Package source denotation, scalar/module structure, coverage and concrete realizers separately. Use the correlated-list plane, empty element type and guarded length=100 as distinct acceptance/refutation fixtures. Keep field and integer/torsion formulations honest.
6. **Use analytical transfer to exercise binder order.** A real regional differentiation interface and weighted Fubini interface test more than arithmetic. Preserve attained-range derivatives, restricted measures, strict/weak fibers and countable a.e. collection. A tiny opaque atom fixture is not a test of these Lean semantics.
7. **Add export hygiene to the acceptance boundary.** Every accepted authored program should produce the intended well-scoped Lean statement under arbitrary legal source identifiers. Compile generated adversarial examples, not only shipped examples. Source mapping and name qualification are part of reliability, even where kernel checking catches failures.
8. **Keep the kernel experiment subordinate to a measured problem.** A proof-explicit refinement former is mostly a representation variant of subtypes. If dependent coercion normalization is the real issue, compare proof-emitting canonicalization against the best ordinary library version before adding conversion rules.

The strongest unified result from this lane is a staged, testable architecture: determine meanings and witnesses; ground a finite theorem profile; retain conditional evidence and its alternatives; reconstruct exact proofs; distinguish accepted nodes from complete documents; measure the added interface against the same mathematical tools. The immediate evidence supports those components in small different fragments, while leaving the end-to-end Lean authoring interface as the next substantive experiment.
