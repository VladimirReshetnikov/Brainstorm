\section{Report cards}\label{app:cards}
One paragraph per report: what it proposes, what it proves, what it ran, and what this review found when it compiled and reran it. Page and line counts are in Table~\ref{tab:material}.

\subsection*{Alder}
\emph{Residual Types and Proof-Producing Mathematical Elaboration.} The judgment $s\rightsquigarrow(p:T)\;!\;\Delta$ with the exclamation mark read as an elaboration effect; the antichain algorithm with $\oplus$ and $\otimes$ and Theorem \ref{thm:antichain} in its ``termination and exact residual alternatives'' form; a $t^k$ grounding bound; the frame theorem over an abelian group with integer combinations and the torsion warning; a residual-to-root theorem needing only a unit constant coefficient; the germ example with its Catalan closed form, radius $9/64$ and error bound; a typed \emph{without loss of generality}; the a.e.-to-pointwise upgrade under full support. Companion Alder-0: parser with lexical blocks, antichain engine, separate checker, exporter; 64 unary graphs exhaustively, 200 conjunctive graphs, 46,875 frame comparisons, 33 germ coefficients; two example modules rejected by design (a scope leak and an unused unproved claim). Answers both question sets in one appendix. This review: two Lean exports compile (one with ten unused-variable lints); all counts reproduce.

\subsection*{Bryony}
\emph{Contract-Indexed Mathematical Reasoning with Proof-Carrying Requirements.} The judgment $e:A\triangleright P\;!\;\{(S_i,t_i)\}$; the same antichain theorem stated as conditional soundness plus termination and relative completeness; two-layer completeness (ground engine, generation profile) and epochs; the weighted subgraph Fubini example under s-finite measures with the strict/non-strict sibling and a point-mass separator; the observation-consumer registration $R(x,y)\to S(C(x),C(y))$; the ATMS and provenance attribution. Companion: parser, solver, replay checker on full source snapshots, exporter; 23 methods, 400 systems, 3,873 subsets, 1,835 replayed certificates, 288 positive Frey triples. Two crosswalk tables. This review: one Lean export compiles (two lints); all counts reproduce.

\subsection*{Clover}
\emph{Scoped Mathematical Reasoning with Obligation-Directed Types.} Obligation telescopes with pending and closed transitions; goal-triggered grounding with a source-derived arena and the bound $rM^v$; the closure theorem (single route, not antichain); the affine test-basis theorem over a field with the three-observation correlated example $(|xs+\!\!+ys|,|xs|,|ys|)$; the a.e. quantifier trap; the sharpened $p\ge2$; a five-gate implementation plan. Companion: the endomorphism slice (four properties, seven rules, scopes, plan checker, exporter) and an exact affine program; 35 methods, 1,576 assertion checks, the 211-versus-16 profile comparison. This review: \code{CloverCore.lean} compiles with all seven rules axiom-free; \code{GeneratedExamples.lean} needs the core compiled to an \code{olean} first and then compiles with three lints; all counts reproduce.

\subsection*{Fennel}
\emph{A Proof Language of Stable Objects and Explicit Requirements.} Frontier labels $L(q)$ with the residual formula $R_q$; the finite frontier theorem; the strict sealing rule (a metavariable-free target); \code{using only} as the first method mechanism; the q-Pochhammer example where the logarithmic form has guards the product form lacks; the two-point basis on \code{List Nat} and its failure on \code{List Empty}. Companion: planner with quotas, independent certificate checker that verifies even unused nodes, exporter; 27 boundary tests, 2,000 graphs, 12,872 comparisons, 1,820 certificates, the exponential family to 1,024 routes. No crosswalk table; the questions are answered in the text. This review: four Lean exports compile (lints only); all counts reproduce.

\subsection*{Heather}
\emph{Proof-Carrying Mathematical Interfaces.} Facets and rows; the closure proposition (single route); the realizable affine frame over $\Q$ with the rank proposition; the distinction between an empty admissible type and an empty element type; the affine-inequality warning ($1-n$); a Lipschitz enclosure propagation; the behavioural slice as the first deliverable. Companion: a list-length frontend with four fixed frames, certificate rechecker, concrete negative witnesses, a toy use-site resolver; 18 methods, 7,500 comparisons, 466 witnesses, 14 corrupted certificates refused. T1--T10 table. This review: four of the five Mathlib exports compile; \code{even_reverse_length.lean} fails because the template's \code{omega} runs after \code{simp only} has closed the goal, and compiles without that line. All 18 tests reproduce; the use-site demo needs \code{PYTHONUTF8=1} on Windows.

\section{Experiments and reproducibility}\label{app:repro}
All Lean runs used a ProveIt checkout at commit \code{24ce8bd7} with toolchain \code{leanprover/lean4:v4.32.0} and Mathlib as pinned there, invoked as \code{lake env lean <file>} from the ProveIt root. The \code{experiments/lean/} directory of this report contains:
\begin{itemize}
\item the twenty shipped Lean files, copied verbatim from the nine archives and renamed \code{<Report>__<path>.lean}, with the compiler log of each run beside it (\code{.log});
\item \code{clover/}: \Cl's core compiled to an \code{olean} with \code{lean -o} from inside the ProveIt root (the compiler refuses output paths outside its root) and \code{GeneratedExamples.lean} compiled against it with the directory prepended to \code{LEAN_PATH};
\item \code{ListImage.lean} and \code{FreyRoutes.lean} with their logs (Sections~\ref{sec:frames-lean} and~\ref{sec:routes});
\item \code{summary.txt}, the per-file exit codes, elapsed milliseconds, and diagnostic counts.
\end{itemize}
The companion reruns are in \code{experiments/companions/}: one log per command (Table~\ref{tab:runs}) and \code{summary.txt} with exit codes and elapsed times. The companions were run from a scratch copy of each archive because several rewrite their own result files; the copies are not included, the archives are unchanged under \code{docs/round-4/ideas/}.

Timings are single wall-clock runs on one Windows machine and are not comparable across files: the first \code{lake env lean} of a session pays a toolchain start (\Al's 18-line \code{Locality.lean} took 77 s for that reason and its sibling 7 s), and the first Mathlib import of a session is cold (\He's 8-line \code{UseSite.lean} took 689 s; the next Mathlib file 92 s; \code{FreyRoutes.lean} 220 s while another Mathlib job ran).
